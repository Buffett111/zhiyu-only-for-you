# urTube 影音分析模組

在模組探索啟用「影音分析」，或由側邊欄進入。沿用知隅登入與個人版面設定，觀看紀錄、匯入紀錄及分類均保存於本機 PostgreSQL，依登入帳號隔離。主要入口為 Chrome 擴充功能，自動擷取 YouTube 觀看紀錄頁及之後的播放；檔案匯入保留作為備份相容方式。不包含交友配對。

## 自動擷取 YouTube HTML

網站提供擴充功能 ZIP。解壓縮後，在 Chrome 擴充功能管理頁開啟開發人員模式、載入未封裝項目；開啟擴充功能並按「授權並連接知隅」，允許 YouTube 網站存取，再於知隅連接分頁確認目前帳號。每個 Chrome 設定檔需分別安裝；手機可直接查看已同步結果。

擴充功能直接開啟已登入 YouTube 的 /feed/history 頁，持續捲動並解析新載入 HTML，辨識日期分組、影片與 Shorts。不使用 Chrome history API，沒有 Chrome 全站瀏覽歷史權限，也不把手動 Takeout 匯入當成日常流程。首次完整回補沒有固定一年或五年截止，會讀到來源實際提供的歷史起點；Google 已刪除、自動刪除或關閉紀錄的部分無法還原。

每批最多 200 筆，本機待傳佇列最多 10,000 筆；主機失聯或佇列滿時保留尚未確認的批次並暫停往下載入，恢復後續傳。頁面保留最近 40 個日期區段的內容，其餘以等高空白取代以限制 DOM 增長。載入緩慢、continuation 暫時消失或頁面結構未辨識時，都不靠逾時宣告完成。重試退避為 10／20／40／60 秒，先向上捲離載入區，再回到底端重新觸發觀察器；若 continuation 裡有重試按鈕，僅點擊該範圍。含載入元件的日期區段不壓縮。只有 YouTube 顯示明確歷史結尾、無載入元件且經三分鐘確認，才記錄完整覆蓋；沒有結尾訊息的版型會繼續等待，用戶可在擴充功能暫停。完整掃描後每日執行近期增量，重疊兩天並去重。

最早已讀日期及執行狀態保存在擴充功能。若 Chrome／分頁關閉，已同步資料仍在主機，待傳紀錄留在 Chrome；重新回補會從最新頁重新載入、跳過已保存的重複事件，並非依靠不穩定的 YouTube 內部 continuation token 直接跳到舊頁。來源頁日期精度僅為一天，同影片同日合併成一筆，無法推論當天重看次數。新播放每 2 秒檢查播放器，約每累積 15 秒送入佇列，排除暫停、跳轉和可辨識的廣告；最後尚未送出的少量秒數可能在強制關閉頁面時遺失。

## 帳號綁定與撤銷

所有寫入仍須通過既有 Cloudflare Access。擴充功能透過專用知隅同源分頁發出請求，保留 HTTP Origin 與 Access 驗證，沒有新增公開匿名擷取入口。登入過期時提示重新登入，期間暫存資料。

後端同時驗證登入 user ID 與獨立裝置憑證，切換知隅登入帳號不會把舊佇列送進另一個人的資料庫。裝置憑證只存在擴充功能受信任儲存區，資料庫僅保存 SHA-256；網頁裝置列表不提供憑證。撤銷裝置與同步使用同一個模組鎖，清除影音資料也解除全部裝置，以避免稍後的同步重新建立已刪紀錄。最多連接 10 個瀏覽器。

擴充功能不讀取 Google Cookie 或登入憑證，不新增 AI 自動呼叫；取得的是該 YouTube 分頁目前登入帳號的內容，開始前請核對 YouTube 與知隅兩邊的帳號。安裝到共用 Chrome 設定檔時，應了解其中可能出現不同 YouTube 帳號的活動。

來源：[Chrome content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)、[選用權限](https://developer.chrome.com/docs/extensions/reference/api/permissions)，HTML 日期與內容解析參考 urTube MIT 程式碼。

## 匯入與匯出

- urTube Account 的 portable export ZIP v1：讀取觀看事件、影片中繼資料、日期精度與目前 active 版本的主題分類；不讀入帳號憑證、搜尋與社交資料。
- Google Takeout 的 YouTube 觀看紀錄：ZIP、原始 watch-history.json 或 HTML。支援常見多語系日期；無法辨識時會回報，建議改用 JSON。
- 知隅自己的影音 JSON 匯出，可重新匯入。

每次最多 50 MiB、20 萬筆觀看紀錄，選取的 ZIP 內容解壓縮後最多 200 MiB；帳號最多 50 萬筆。完全相同檔案以雜湊去重，事件依影片 ID、時間與精度去重。相同台北日期的精確事件會取代日期精度事件；來源沒有時間精度時，無法分辨同日重看次數。不同來源名稱不影響相同事件去重。

網站匯出以每卷最多 5,000 筆切分；資料較多時請依序下載所有分卷，重新匯入時亦逐卷操作。分卷期間請避免同時新增或清除紀錄。個人分卷包含逐筆觀看資料、影片長度、進度及影片主題；頻道分類與人工更正由站長的標準加密資料庫備份保存，後者是完整一致快照。匯出的 JSON 本身未加密，請妥善保存。

## 分析與資料限制

提供近 28 天、90 天、一年及全部紀錄，期間以目前時間向前計算；舊資料可切換全部查看。卡片包含觀看次數、不同影片、活躍日期、觀看分布、頻道排行、主題與可搜尋的逐筆紀錄。卡片顯示與排序隨帳號同步。

保存日期、頻道、影片長度、觀看進度百分比、續播位置及實測秒數。時數優先採實測；只有日期的歷史列沿用 urTube 規則，以進度／續播位置估算，以片長及每筆 600 秒為上限；只有片長時不估算觀看時間。原始片長與進度不截斷，估算可以日後重新計算。畫面列出進度估算、僅片長推估、實測與缺值筆數；估算不代表完整觀看。Takeout 缺少時長時不憑空填入。次數是匯出檔可辨識的事件數，不保證等於所有實際播放次數。主題可複選，占比可能超過 100%，分類描述影片內容而非觀看者的身份或立場。

## 按需 AI 分類

使用現有後端 OpenAI 設定，模型為 gpt-5.6-luna。每按一次預設最多分類 400 部尚未分類的影片，分成最多 4 個並行批次，每批 100 部，只傳送影片 ID、標題及頻道名稱，使用 Responses API、store:false；不傳送帳號或觀看時間。即使僅有標題，所選影片仍可能反映私人興趣，使用者應在閱讀畫面說明後自行啟動。結果按帳號保存，既有 urTube 主題保留。輸出必須完全對應輸入影片 ID，格式錯誤不寫入結果。

影音與財經新聞共用 AI_DAILY_REQUEST_LIMIT（預設全站每日 40 次），每批只占一次；瀏覽已存資料不呼叫 AI。錯誤亦消耗一次預留額度以防無限重試，並有等待時間。實際 tokens 記入 ai_daily_usage，費用依 token 用量計算，次數限制不是美元上限。頻道背景分類須先取得帳號本人的啟用同意；已保存結果的瀏覽不增加 API 呼叫。

## API 與維護

所有路徑以 `/api/v1/media` 開頭：`POST /import` 接收 application/octet-stream；`GET /summary`、`GET /history` 支援 range；`POST /classify`、`POST /clear` 要求 `{confirm:true}`；`GET /export?part=1` 匯出指定卷，不帶 part 可串流匯出整份資料。私人回應禁止公開快取，寫入需同源驗證。API 不接受使用者指定資料擁有者。

資料庫遷移 007 新增 media_events、media_imports、media_classifications、media_ai_state。停用保留資料，清除只影響目前帳號；清除後尚未完成的 AI 工作不得重新建立資料。加密備份／還原沿用既有操作流程，包含全部影音表格。

來源：[urTube](https://github.com/skyhong2002/urtube.observe.tw)，參考提交 `5b2904401b1bb44a41d4095d16e57865211e8996`。日期解析部分依 MIT 授權改寫，詳見根目錄 THIRD_PARTY_NOTICES.md。

遷移 008 新增 media_devices；連接與同步 API 位於 /api/v1/media/devices、/api/v1/media/extension/sync，受既有登入與同源政策保護。npm run build 會依 PUBLIC_ORIGIN 產生專屬擴充功能 ZIP；打包過程不讀取或嵌入金鑰，未設定時使用保留測試網域。

## 頻道探索與背景資料管線（1.2）

- 現代 YouTube lockup 的頻道名稱可能只有普通文字或頭像的 aria-label，不能只找頻道超連結。擷取器同時支援這些結構；舊的空白頻道由背景補齊，不要求刪除重匯。
- `media.metadata` 每分鐘分批處理已啟用帳號實際保存的影片，每帳號每輪預設最多 180 部、6 個並行請求。YouTube oEmbed 取得公開作者與片名，公開頻道頁的 identifier 提供穩定 UC ID；讀到 ID 即取消其餘下載，同一頻道在程序內共用請求。沒有 Google Cookie、搜尋紀錄或觀看時間傳出。成功資料快取 30 天，無法提供者 7 天，暫時失敗 30 分鐘。
- 頻道探索提供全部頻道搜尋、分類篩選、分頁、次數／時數排序、個人觀看影片明細及覆蓋率。資料補齊與 AI 分類是不同狀態，畫面不因背景更新而清空閃爍。
- 來源標籤沿用 urTube 2026-09-05 的三個內容軸定義：新聞 `tagid=13`、個人社論 `tagid=1&not=2,9,10,12,13,33,36,81`、社論節目 `tagid=1,9`。下載整份公開清單後在本機比對 ID／handle，不以名稱猜測，不把私人清單送給來源。顯示來源時間、內容雜湊及最長六小時的快取；驗證失敗時隱藏來源標籤。這三份清單並不是涵蓋所有題材的 taxonomy。
- 使用者同意後，自動以 GPT-5.6 Luna 整理頻道內容，每批預設最多 32 頻道、4 批並行，每頻道最多 8 部影片，優先抽取不同月份的公開片名。只傳公開 ID、頻道名稱與標題，不含帳號、日期或時長。每天每帳號預設最多 200 批，並共享全站 AI 上限；錯誤也計入預留次數，一般錯誤等候十分鐘；429 依 Retry-After 等候 1–60 分鐘再續做。
- 輸出必須一一對應頻道，引用必須存在於所給影片標題；信心小於 0.65 或無可驗證依據改列「無法判斷」。保存模型、定義版本、輸入雜湊、信心與引用，標示為 AI 建議。使用者可確認／更正，亦可恢复原始 AI 建議；不推斷觀看者的身份與立場。既有分類不因每次增量同步而重新付費生成。此版是固定內容類別的頻道分類，尚未移植 urTube 的完整個人 taxonomy 候選版評估與啟用流程。
- 新 API：`GET /channels`（range、q、category、page、sort）、`GET /channel`（key、range）、`PUT /channel-automation`（enabled、confirm）、`PUT /channel-category`（key、category；null 恢復建議）。全部按登入帳號查詢，不能指定別人的 user ID。停用／撤回自動分類／清除資料後，未完成的 AI 回應不能重新寫入。
- 遷移 009–011 新增私人 metadata、頻道分類、處理狀態及觀看進度欄位。`npm run build` 產生 1.2.0 擴充功能；更新未封裝版本後需在 Chrome 重新載入，再按重新回補。原佇列及裝置綁定維持。

參考：[urTube 個人 taxonomy v2](https://github.com/skyhong2002/urtube.observe.tw/blob/main/docs/personal-taxonomy-v2.md)、[頻道標籤政策](https://github.com/skyhong2002/urtube.observe.tw/blob/main/docs/channel-tag-policy.md)。

## 並行批次與頻道頭像

- `MEDIA_CHANNEL_BATCH_SIZE=32`、`MEDIA_VIDEO_BATCH_SIZE=100`、`MEDIA_AI_CONCURRENCY=4`、`MEDIA_AI_DAILY_BATCH_LIMIT=200` 可由站長調整。全站 `AI_DAILY_REQUEST_LIMIT` 仍有效；範例維持保守的 40 次，正式站由站長授權提高到 500 次／日。API credit 餘額不是無上限請求許可，次數也不是金額上限。
- 每輪先在資料庫鎖定該帳號與全站用量，預留非重複項目及所需批數；餘額不足時只執行容許的批數。網路請求不持有交易，各批成功即獨立保存。單批失敗不重跑已保存分類；Token 歸入預留當日，跨午夜不錯記日期。
- 工作有效期十分鐘，重啟後等待有效期過去才接續；若主機在 API 已收費但本機還未保存時中斷，仍可能重新請求未保存的批次，不能保證跨服務 exactly-once。暫停／清除／停用會使舊結果無法寫回。
- YouTube 影片資料、頻道圖片與 AI 分類獨立進行。圖片由公開頻道頁的 `og:image`／`itemprop=image` 取得，只接受 YouTube 頭像 CDN 網址，正常快取 30 天、缺图一天、失敗一小時。每帳號每輪最多 60 個頻道、3 個並行擷取。列表和頻道詳情顯示公開頭像，圖片失敗回退文字。瀏覽器載入圖片時不傳送知隅網址作為 Referer。
- 遷移 012 新增頭像快取與並行／重試狀態。頭像隨個人影音清除一起刪除；標準加密資料庫備份涵蓋新增表。

## 時間依據與八小時回補目標

- 遷移 013 只重新計算衍生估算值，保留原始資料。僅有片長、不含播放位置或進度的紀錄不再增加觀看時數。實測不存在時，概況顯示「—／尚無實測資料」，不將 null 轉成 0.0；短於 0.1 小時的實測顯示秒數。
- 歷史進度推估獨立顯示，不和實測相加作為主要時數；歷史進度不是每次觀看的實際耗時，保留每筆十分鐘限制並在畫面說明。
- 排程拆成 `media.metadata`、`media.icons`、`media.classify` 三條獨立佇列，每分鐘觸發、各自使用跨程序互斥。舊 `media.enrich` 排程取消，已排入的舊工作仍可安全完成。
- 影片驗證 `MEDIA_METADATA_BATCH_SIZE=180`、`MEDIA_METADATA_CONCURRENCY=6`。少數影片錯誤不阻止整輪處理；連續两組全部失敗時停止本輪。YouTube 429 會保存五分鐘跨帳號冷卻，圖片擷取也遵守冷卻；單筆錯誤維持三十分鐘後重試。
- 頁面顯示近十分鐘完成速率與「目前清單」剩餘時間。它是動態估計；繼續回補新歷史紀錄或來源限流時，預估會變動。API credit 不會提高 YouTube 來源可用性，八小時是目標而非服務保證。

## 短時間與未知值的顯示

- 影片列、頻道列表／詳情、歷史推估總計與回補預估統一使用自適應單位：12 秒顯示「12 秒」、84 秒顯示「1 分鐘 24 秒」，不再取整成 0 分鐘或 0.0 小時。正值不足一秒顯示「不到 1 秒」，低於 0.1% 的正進度亦不顯示成零。
- 頻道缺少時間依據時顯示「時長未知」，並列出有時間資料的筆數／全部觀看筆數；避免把部分紀錄的時間當成全部觀看的總時間。保留實測零、未知與正數的差異；不為了消除畫面上的零而更改原始資料或估算公式。
