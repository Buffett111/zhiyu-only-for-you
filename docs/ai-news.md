# AI 新聞摘要與分析

新聞卡片提供按需產生的繁體中文摘要。使用 OpenAI Responses API 的 `gpt-5.6-luna`，不會在開啟網頁或排程擷取新聞時自動產生費用。原有每日摘要仍採規則整理。

## 分析範圍

- 目前選定標的、新聞／公告及 ETF 分類，最近七日最多 30 則。先讀取最多 500 則候選，全部分類優先保留標的本身、成分股及市場背景各 10 則，再補滿剩餘名額。
- 資料庫目前只有標題、日期、來源與連結。模型沒有閱讀全文；畫面固定標示此限制。報導重點、可能影響與待查證事項分開，日文及英文標題也整理為繁體中文。
- 每個分析段落必須引用本次提供的來源 ID，後端驗證格式與 ID，連結由原始資料建立，不採用模型自造 URL。這只能驗證引用存在，不能保證推論正確。
- 傳送公開標的資訊及新聞標題，不傳送帳號、Email、持有狀態、分組或整份私人清單。來源視為不可信資料，模型沒有工具權限。API 設定 `store: false`，不等於供應商所有紀錄均為零保留。

## 儲存與費用控制

- `news_analysis` 保存每個標的／分類的最新成功分析、來源快照、模型、時間、token 用量及最新嘗試狀態。更新成功會替換該分類舊結果；失敗保留舊結果並標示錯誤。這是最新摘要快取，尚無歷次版本閱讀介面。
- 模型、提示版本或選入新聞內容改變後才需要重新產生；相同內容直接共用資料庫結果。新聞已變更時標示舊結果，等待使用者按下更新。
- PostgreSQL 列鎖協調並行請求，避免同份分析重複呼叫；當機中的 pending 工作 90 秒後可以再次嘗試。成功後 15 分鐘、失敗後 5 分鐘內限制新嘗試。
- `ai_daily_usage` 以台北日期原子計數。全站預設每日最多 40 次新嘗試（含失敗），可透過 `AI_DAILY_REQUEST_LIMIT` 調整，設為 0 停用產生。成功回覆的 token 數也會累計。供應商可能已處理但本機逾時的請求無法完整計入 token，以 OpenAI 帳單為準。
- 每次輸出最多 2,600 tokens，不使用付費搜尋工具，不自動重試 API。入口僅這個 POST 允許等候 65 秒，其餘 API 仍為 12 秒。
- 金鑰只保存在後端 `.env` 的 `OPENAI_API_KEY`；不要加 `VITE_` 前綴。`.env` 已忽略，發佈掃描另外檢查 API 金鑰內容。
- GET 與 POST 都要求登入、啟用財經模組，且標的屬於目前使用者的追蹤清單。共用摘要只含公開市場資料，移除私人清單不會刪除其他人使用的市場快取。整個資料庫的加密備份包含摘要。
